# Универсальность: работа на незнакомом шаблоне

На финальной защите сервис получит шаблон, которого не было в датасете. Поэтому качество
проверяется не на трёх шаблонах VK, а на **слепом наборе**, которого разработка не видела,
и отдельно контролируется отсутствие подгонки под датасет.

## Слепой набор (31 шаблон)

| Группа | Шаблонов | Чем трудна |
|---|---|---|
| Шаблоны LibreOffice Impress (`.otp` → `.pptx`) | 23 | другой «производитель» OOXML; все плейсхолдеры с одинаковым `idx=0`; 1–13 примеров; нестандартные размеры 11.02×6.2″ и 11.02×8.27″ (≈A4); текстурные и фото-фоны; «мусорная» тема по умолчанию |
| Шаблон питча ЛЦТ-2026 | 1 | сторонний реальный шаблон: 37 слайдов, 825 изображений, нативные диаграммы и фото-плейсхолдеры, свои макеты «Команда», «Статистика», «Стадии» |
| Синтетические (`decksmith/testing/synthetic.py`) | 4 | 4:3 без единого слайда; бренд с колонтитулами и повторяющимся текстом на каждом слайде, обложкой-текстбоксом, нативными таблицей и диаграммой; тёмная тема; макеты без единого плейсхолдера (как в Google Slides) |
| Датасет VK (контроль) | 3 | — |

Методика (`scripts/stress.py`): для каждого шаблона — разбор как незнакомого → один и тот же
план из 12 слайдов (все типы: обложка, содержание, KPI, раздел, карточки, шаги, диаграмма,
таблица, текст, цитата, карточки, финал) → 3 варианта → сборка → рендер LibreOffice →
детерминированный аудит. Метрики: балл аудита, ошибки, совпадение числа слайдов, падения,
различимость вариантов (минимальная доля слайдов с разными макетами между парами вариантов).
Таблица по каждому шаблону — [STRESS_RESULTS.md](STRESS_RESULTS.md).

## Что было не так и что сделано (всё — общие механизмы)

| Симптом на слепых шаблонах | Корневая причина | Общее решение |
|---|---|---|
| Пустые слайды, пропавший текст (LibreOffice-шаблоны) | у всех плейсхолдеров макета одинаковый `idx=0`, наследование «по idx» давало телу геометрию заголовка | у каждого плейсхолдера нового слайда фиксируется геометрия его пары в макете; слоты ищутся по idx, иначе по положению |
| Акцент = цвет фона, одинаковый зелёный у 8 шаблонов | при малом числе примеров акцент брался из неиспользуемой темы по умолчанию | акцент = самый частый насыщенный цвет из элементов **и рендера**, обязан быть виден на фоне; темы учитываются, только если реально используются |
| Кегль текста 32 pt, массовое переполнение | размеры плейсхолдеров по умолчанию | роли кеглей ограничены долями высоты слайда, когда примеров мало; ужатие «раздутых» плейсхолдеров до кегля текста шаблона |
| Контент за нижним краем (Blueprint) | CV-оценка свободной зоны на текстурном фоне (сетка чертежа) дала полоску 3% высоты | распознавание текстурного фона → зона под заголовком + подложка для читаемости; регион всегда в пределах слайда |
| Поля 2.4″ и нулевая зона контента (Metropolis) | поля считались по одному примеру | поля по умолчанию при недостатке данных и ограничение разумными долями |
| Каскад ошибок после сбоя одного слайда | полусобранный слайд оставался в колоде | упавший слайд удаляется целиком перед фолбэком |
| Заголовок растёт за верхний край | многострочный заголовок в рамке, рассчитанной на строку | заголовок вписывается строго в свою рамку по шкале кеглей; остаток — на сокращение LLM |
| Обложка без плейсхолдера заголовка не распознаётся | заголовок искался только в верхней трети | доминирующий текст в любом месте слайда |
| Колонтитулы/повторяющиеся надписи удалялись | считались незаполненными слотами | `FOOTER/DATE/SLIDE_NUMBER`, поля слайдов и текст, повторяющийся у края на большинстве примеров — бренд-элементы, переносятся и на слайды из голых макетов |
| В клоне таблицы/диаграммы оставались данные шаблона | нативные таблицы/диаграммы примеров не перезаполнялись | таблица перезаполняется с сохранением стиля (строки/колонки клонируются), диаграмма получает свою копию chart-части и `replace_data` |
| Раздел/финал собирались пустым списком | в шаблоне нет паттерна раздела | нативная композиция раздела в токенах шаблона; обложка может служить разделом |
| Варианты почти одинаковы | каждый вариант выбирал лучший паттерн независимо | выбор по очереди со штрафом за паттерн, уже взятый другим вариантом (обложка одна на все варианты) |
| Ложные «наложения», «выход за край», «логотип» | нарушения, заложенные в самом шаблоне | аудит сравнивает с исходным примером/макетом и помечает «так в шаблоне» (info); логотип — только малый объект у края; колонтитулы макета — только если есть на слайде |
| `.potx`, `.ppt`, `.odp` не принимались | только `.pptx` | нормализация входа: смена content-type для `.potx/.pptm`, конвертация остального через LibreOffice |
| Кегль уменьшался, хотя в карточке шаблона было место | текст вписывался строго в исходную рамку | по разъяснению организаторов рамка растёт внутри своего блока (карточки, плашки; вне блока — до полей и ближайшего объекта, в обход логотипов и колонтитулов), кегль уменьшается только потом |
| Текст карточек компоновщика выходил за карточку (Grey_Elegant, Yellow_Idea, Freshes) | карточки фиксированной высоты, кегль упирался в минимум | карточка вытягивается под текст внутри зоны контента, один кегль на весь ряд; новая проверка `layout.block_overflow` ловит текст за пределами блока |
| Слово рвалось посередине в узкой карточке | минимальный кегль не учитывал самое длинное слово | кегль уменьшается под самое длинное слово |
| Сгенерировано 11 слайдов вместо заказанных 12, аналитический вариант — 9 (разбор реального прогона на VseGPT) | модель вернула на слайд меньше и после раунда починки; аналитический вариант выбрасывал разделители | план детерминированно добирается до заказанного числа («Главное», «Содержание», затем разбиение длинных списков); все три варианта одной длины: у аналитического «Содержание» становится «Главным» в начале, разделы — сводкой раздела |
| Пропал призыв к действию на финальном слайде и подпись разделов | у макета финала/раздела нет рамки подзаголовка | ведущая строка идёт в свободную подпись (аватар рядом убирается), без неё выбор штрафует макет; аудит `integrity.content_lost` проверяет эти строки |
| Автоисправление сделало весь текст рамки 24 pt, пункты уехали на логотип | аудит мерил рамку «крупный лид + мелкие пункты» одним кеглем первой строки, фиксер ставил всем абзацам один кегль | замер по абзацам: свой кегль, интервалы до/после, межстрочный; фиксер уменьшает смешанную рамку пропорционально; в вёрстке лид уступает первым |
| Подзаголовок наложился на вторую строку заголовка, аудит счёл это «так в шаблоне» | в примере заголовок в одну строку, подзаголовок начинается внутри его рамки | заголовок держится выше следующей заполненной рамки; выбор штрафует макеты, где заголовок пришлось бы ужать; «так в шаблоне» — только если строки пересекались и в примере |
| Подпись слева приписана к карточке справа | для колонки элементов радиус по горизонтали был равен ширине слайда | вдоль оси без шага решает зазор между рамками |
| 4 карточки в сетке на 3 колонки: одна висит внизу | сетка из 6 сокращалась до 4 | штраф за «сироту» в последней строке — выбирается ряд из 4 |
| Таблица шаблона на 10 строк выходила за слайд и рвала слова | Google Slides сохраняет фиктивную рамку таблицы 3000000 EMU, реальный размер задаёт сетка колонок | размер таблицы берётся по сетке; кегль ячеек подбирается под высоту до нижнего поля; если данные не помещаются читаемо — нативная перерисовка по реальной ширине |

## Второй проход: питч на шаблоне ЛЦТ-2026 как «слепой» боевой тест

Питч проекта собран самим DeckSmith (`configs/pitch.yaml`: готовый план
`docs/pitch/pitch_plan.json` + документация проекта как контент-пакет) на шаблоне ЛЦТ-2026,
которого не было в датасете. Всё найденное исправлено **общими механизмами** и перепроверено
стресс-тестом на всех 31 шаблонах.

| Симптом | Корневая причина | Общее решение |
|---|---|---|
| Текст карточки над её заголовком, рамки поменялись местами | python-pptx отдаёт плейсхолдеры слайда отсортированными по `idx`, а их клоны идут в порядке документа | пары «плейсхолдер слайда ↔ макета» сопоставляются в порядке документа (регрессионный тест) |
| Заголовок заезжает под логотипы партнёров в полосе заголовка | фон макета несёт графику там, где рамка заголовка | CV «чистой» части полосы заголовка (края по RGB-каналам; длинные линейки-подчёркивания не считаются) → рамка заголовка укорачивается; бюджет длины заголовка для модели учитывает это |
| Длинный заголовок «вываливается» с цветной плашки | плашка — отдельная фигура по ширине слов примера | плашка (залитая фигура, на которой начинается текст) подгоняется под новый заголовок |
| Фиолетовый заголовок на фиолетовой карточке | так нарисовано в самом макете | цвет слота < 3:1 к тому, что под ним в рендере → самый читаемый из текстовых цветов шаблона |
| «Стена логотипов» партнёров использовалась как карточки | служебный слайд не распознавался | ≥ 10 мелких картинок при малом числе текстов → `guide` |
| Пустые полупрозрачные карточки в PDF/HTML | LibreOffice рисует окрашенные плейсхолдеры макета даже на слайдах, где их нет (PowerPoint — нет) | такие плейсхолдеры находятся по XML и подтверждаются пробным рендером; селектор не оставляет их пустыми, «холст» выбирается без них |
| Контент прижат к верху, низ пустой | мягкое свечение фона считалось «занятым» | области без резкой границы — часть фона; снизу зона ограничена колонтитулами макета и безопасным полем; цвета текста проверяются ко **всем** цветам рендера под блоком |
| Пустые фото-рамки, пустые слоты внутри карточек, «скрытые» элементы на голых макетах | фото нет, у элементов нет значений, скрыть рамку макета нельзя | штрафы селектора: пустые фото-области, пустые слоты элементов, длина заголовков элементов против слота; скрывать элементы — только на примерах-слайдах |
| Рамка-карточка заголовка элемента накрывает его текст | рамка заголовка во всю карточку, текст внутри неё | рамка, содержащая следующую рамку того же элемента, владеет только местом над ней |
| Пропали числа KPI, слово обрезано на полуслове | при превращении KPI в список/карточки без числового слота значение терялось; заголовок карточки резался до 40 символов | значение ведёт заголовок/пункт; заголовок не режется, длинная «голова» остаётся текстом |
| Серии диаграммы одного цвета на тёмном фоне | цвета серий не проверялись на фоне | серии — видимые на фоне и различимые между собой цвета палитры шаблона |
| В «визуальном» варианте диаграмма стала таблицей | диверсификация штрафовала «чужой» способ показа данных | способ показа данных — «лицо» варианта: первое доступное из его `represent.data` |
| Раздел/финал поверх графики шаблона | композиция раздела по фиксированным координатам | раздел и финал ставятся в свободную зону макета, найденную CV |
| «Макет «Сравнение» (заголовки + тела колонок) читался как 4 одинаковые карточки | заголовки и тела колонок имели одну типографическую сигнатуру | рамки плейсхолдеров, различающиеся по высоте больше чем вдвое, не считаются одинаковыми элементами |
| Ложные «наложения» | сравнивались рамки, а рамка-карточка содержит рамку текста по замыслу шаблона | аудит сравнивает положение строк (с учётом вертикальной привязки); пересечение только рамок — предупреждение, «так в шаблоне» — не ошибка |
| «Число 25 не найдено в материалах» | кэш поля номера слайда из примера | кэш `slidenum` обновляется; номера, даты и колонтитулы не проверяются как факты; зато проверяется, что значения KPI видны |
| Разбор шаблона однажды занял 15 минут | загрузка шрифтов без общего бюджета (до 6 семейств × 9 URL × 20 с) | Google Fonts CSS API (в т.ч. «Montserrat Medium»), бюджет 15 с, пауза после сетевой ошибки; рендер LibreOffice в своей группе процессов с жёстким таймаутом и одним повтором |

Визуальная проверка интерфейса в браузере (генерация, аудит, исправления, выгрузки) добавила:

| Симптом | Решение |
|---|---|
| Без модели колода из 7 слайдов при заданных 12 (ТЗ: 10–15) | офлайн-план добирает 10–15 слайдов из того же материала: длинные разделы делятся, добавляются «Ключевые цифры» и «Главное»; ничего не выдумывается (тест) |
| Заголовок обложки обрезан на полуслове, подзаголовок — служебное `product` | заголовок и подзаголовок берутся из первой фразы брифа по границе слов |
| Слайд-гайд с HEX-кодами бренда считался «карточками» | ≥ 3 кодов цветов на слайде → служебный слайд |
| В HTML «Все слайды» не открывались | сетка превью заменяет сцену, `Esc` закрывает |
| После перезагрузки страницы пропадал результат запуска | интерфейс восстанавливает последний запуск (сервис хранит запуски) |

Отдельно проверено: остальные «выбросы» времени разбора в стресс-тестах (138–944 с) совпадают
по времени со сном ноутбука (`pmset -g log`: сон 908–936 с при закрытой крышке) — это не
код. Стресс-тест и демо нужно запускать с `caffeinate -i` (или с открытой крышкой).

## Гарантии против подгонки

* **Линт в тестах** (`tests/test_blind.py::test_no_dataset_specific_code`): в коде пакета нет упоминаний
  шаблонов датасета, `VK`, имён их макетов («Свободный дизайн»), идентификаторов Google Slides.
* Профиль шаблона не зависит от имени файла (тест), ключ кэша — sha256 содержимого.
* Все эвристики — геометрия, типографика, пиксели рендера и общие RU/EN-ключевые слова типовых
  макетов («Title Slide», «Section Header», «Титульный»…); у каждого решения записана причина
  (`Pattern.reason`, `SlideLayout.rationale`).
* Сквозные тесты на 4 синтетических шаблонах: без ошибок уровня error, балл ≥ 80, различимость
  вариантов ≥ 0.3; бизнес-сценарий «3 колоды < 5 минут» идёт на синтетическом шаблоне.
* Датасет VK не входит в репозиторий: тесты и демо работают без него.

## Проверка пути с реальной моделью

Помимо эмулятора OpenAI-совместимого сервера в тестах (`tests/test_llm_path.py`), весь пайплайн
прогнан на локальной открытой модели **Qwen3-4B** (Ollama, Apache 2.0) на M1 8 ГБ
(`configs/real_model_check.yaml`): план строит модель, 0 упавших вызовов, баллы аудита 85–88.
Это проверка «сантехники» и устойчивости к слабому выводу; целевая модель — Qwen3-32B.
Найденное и исправленное на реальной модели: визуальный аудит больше не отправляет картинки
текстовой модели; вывод модели очищается (поля не по назначению слайда, пункты с переносами и
ручной нумерацией, заголовки на чужом языке, дубли слайдов); структура проверяется на число
разных слайдов и связь названия с брифом с одним раундом ремонта.

## Известные ограничения

* Смысловое качество текста определяется моделью: на 4B встречаются дрейф на английский и
  «придуманные» числа — их ловят `content.language` и `content.numbers_sourced`.
* Если в шаблоне нет ни одного подходящего примера, слайд собирается нативно в токенах
  шаблона: он «в стиле», но проще авторских примеров.
* Встроенные шрифты в формате EOT/MTX не распаковываются; используется одноимённый шрифт из
  Google Fonts или метрически совместимая замена (предупреждение в профиле).
* SmartArt и OLE в примерах не перезаполняются: такие примеры получают низкий приоритет.
* Текст поверх фотографии в примерах шаблона проверяется только по контрасту доминантного цвета.
* LibreOffice (рендер PDF/HTML и аудита) рисует окрашенные плейсхолдеры макета и на слайдах без
  них; селектор этого избегает, но при отсутствии альтернатив пустая подложка в PDF возможна
  (в `.pptx`/PowerPoint её нет).
* Композиция идёт в зоне контента, найденной по рендеру макета: у шаблонов с крупной графикой
  (иллюстрации по краям, заголовок в центре) она мала, и длинный текст карточек ужимается до
  нижней границы шкалы кеглей; при подключённой модели такие фрагменты сокращает скилл `shortener`.
