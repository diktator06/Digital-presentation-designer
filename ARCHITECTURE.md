# ARCHITECTURE

DeckSmith читает чужой шаблон как **набор правил** (дизайн-токены + библиотека
композиционных паттернов), строит структуру колоды по брифу, верстает её тремя
способами строго внутри этих правил и проверяет результат собственным аудитом.

## Пайплайн

```
            ┌────────────── до нажатия Enter (кэш, без лимита времени) ──────────────┐
 .pptx ──► [1 ПАРСИНГ] ─► TemplateProfile            файлы ──► [2 КОНТЕНТ] ─► ContentCorpus
            структура · рендер · CV · паттерны · токены          PDF/DOCX/PPTX/MD/CSV/XLSX, BM25
            └───────────────────────────────────────────────────────────────────────┘
 бриф + Enter ─► [3 ГЕНЕРАЦИЯ]  outline (1 вызов LLM) ─► slide_writer (N вызовов параллельно) ─► DeckPlan
                                   │  изображения (T2I, параллельно) · пиктограммы (Lucide → цвет бренда)
                                   ▼
                 ┌─────────────── 3 варианта параллельно (asyncio) ────────────────┐
                 │ [4 ВЁРСТКА] выбор паттерна ─► clone&fill / compose ─► .pptx      │
                 │            └─ сокращение переполнений (LLM, 1 пакетный вызов)    │
                 │ [5 АУДИТ]  рендер ─► детерминированные проверки + VLM-вопросы    │
                 │            ─► автоисправление безопасных находок ─► переаудит    │
                 │ [6 ЭКСПОРТ] .pptx (нативные объекты) · .pdf · .html (SVG)        │
                 └─────────────────────────────────────────────────────────────────┘
                                   ▼
                 UI: пользователь выбирает замечания ─► фиксеры ─► новая версия колоды
```

Время считается от Enter (как требует организатор): анализ шаблона и контента выполняется
при загрузке. Офлайн-прогон трёх вариантов занимает 10–20 с, с LLM — план ≈ 20–60 с (зависит
от скорости провайдера), остальное параллельно.

## Границы слоёв

Слои общаются только через pydantic-модели из `decksmith/core/models.py` (IR). Геометрия — в EMU
(без потерь относительно файла), кегль — в pt.

| Слой | Пакет | Вход → выход | Детерминированность |
|---|---|---|---|
| Парсинг | `decksmith/parsing` | `.pptx` → `TemplateProfile` | полностью детерминирован |
| Контент | `decksmith/content` | файлы → `ContentCorpus` | детерминирован |
| Генерация | `decksmith/generation` | бриф + корпус + возможности шаблона → `DeckPlan` | LLM (+ офлайн-фолбэк) |
| Вёрстка | `decksmith/layout` | `DeckPlan` × `TemplateProfile` × `Variant` → `.pptx` | детерминирована |
| Рендер | `decksmith/render` | `.pptx` → `.pdf`, PNG | детерминирован (LibreOffice) |
| Аудит | `decksmith/audit` | `.pptx` + PNG + профиль → `AuditReport`; фиксеры | правила — детерм.; VLM — нет |
| Экспорт | `decksmith/export` | `.pdf` → `.html` | детерминирован |
| Оркестрация | `decksmith/pipeline.py` | всё выше, 3 варианта параллельно, manifest | — |
| API/UI | `decksmith/api`, `frontend/` | HTTP + SSE, React | — |

## 1. Парсинг шаблона (`parsing/`)

Шаблоны в датасете устроены по-разному: у VK Tech и VK WorkSpace (экспорт из Google Slides)
макеты содержат почти только TITLE, а весь дизайн нарисован фигурами на **примерах слайдов**;
у VK Education — «правильные» макеты с BODY/PICTURE-плейсхолдерами. Поэтому источником
паттернов служат *и примеры слайдов, и макеты*.

1. **Структура** (`ooxml.py`, `elements.py`): все фигуры разворачиваются из групп с учётом
   аффинных трансформ (`chOff/chExt`); эффективный кегль/шрифт/цвет вычисляется по цепочке
   наследования run → абзац → lstStyle → плейсхолдер макета → мастер → `txStyles` → тема;
   цвета темы разворачиваются через `clrMap` и модификаторы `lumMod/lumOff/tint/shade`.
2. **Рендер** (`render/soffice.py`): LibreOffice отрисовывает примеры и «пробную» колоду — по
   пустому слайду на каждый макет.
3. **CV**: по рендерам определяется тёмный/светлый фон и цвет фона слайда; по пустому макету
   строится сетка занятости 64×36 (края + отличие от фона), и методом гистограммы находится
   максимальный свободный прямоугольник — **зона контента макета** даже при декоративных
   картинках/градиентах.
4. **Паттерны** (`patterns.py`): текстовые элементы кластеризуются по (кегль, жирность, ширина);
   группа из 2–12 элементов с регулярной раскладкой (ряд / колонка / решётка с одинаковым числом
   ячеек в строках) — **повторитель** (карточки, шаги, KPI). Остальные фигуры приписываются
   элементам (карточка-подложка, иконка, номер). Роли слотов: title, subtitle, body, item_title,
   item_text, number, label, person, image, icon, decor. Составные текстбоксы («Заголовок⏎Текст»
   с разным стилем абзацев) получают поабзацные роли. Классификация (title/section/agenda/cards/
   steps/stats/table/chart/quote/image_text/team/contacts/thanks/guide) выполняется правилами по
   геометрии, типографике и RU/EN-ключевым словам **с текстовым обоснованием** (`reason`).
   Служебные слайды (библиотеки иконок, код, образцы палитры) помечаются `guide` и не
   используются как макеты; иконки из них собираются в ассеты. Таблицы/диаграммы, нарисованные
   фигурами, получают низкий приоритет — данные рисуются нативно.
5. **Токены** (`tokens.py`): палитра (частоты цветов текста/заливок/фонов, слияние близких),
   акцент и цвета диаграмм, шрифты заголовков/текста, типографическая шкала и роли кеглей, поля
   (перцентили отступов контента), колонки сетки, каноническая зона заголовка и контента.
6. **Бренд-элементы**: логотипы, колонтитулы, номера слайдов на мастерах/макетах (для аудита).
7. **Шрифты** (`core/fonts.py`): системные → Google Fonts по имени семейства (OFL) → метрически
   совместимая замена; нужно и для рендера, и для замера текста.

Профиль кэшируется по sha256 файла + хэшу кода парсера (`workspace/templates/<id>/profile.json`).

## 2. Контент (`content/ingest.py`)

PDF (PyMuPDF), DOCX, PPTX, MD/TXT, CSV/XLSX → фрагменты, таблицы, нормализованные числа (для
проверки «цифры есть в материалах»). Для больших пакетов — детерминированный BM25-отбор
фрагментов под бриф в пределах бюджета контекста.

## 3. Генерация (`generation/`)

* `outline@v1` — одна LLM-итерация: состав и порядок слайдов, intent каждого, заголовок-вывод,
  опорные факты; в промпт передаются **возможности шаблона** (какие паттерны и с каким числом
  элементов есть) и бюджет символов заголовка.
* `slide_writer@v1` — наполнение каждого слайда (пункты, карточки, данные графика/таблицы,
  иконки, заметки спикера, промпт для иллюстрации) — все слайды **параллельно**.
* Нормализация: валидация pydantic-схемой, один раунд «починки» JSON, согласование intent с
  данными (chart без чисел → stats/text), 10–15 слайдов, титул и финал.
* Офлайн-планировщик (экстрактивный, без модели) — фолбэк и основа тестов.
* Изображения — `images.py` (OpenAI-совместимый `/images/generations`, FLUX.1-schnell);
  пиктограммы — набор Lucide (ISC), растеризуются PyMuPDF в акцентном цвете шаблона.

## 4. Вёрстка (`layout/`)

* **Выбор паттерна** (`selector.py`) — детерминированный скоринг: совместимость intent↔kind,
  точное/сокращаемое число элементов, ёмкость текста, наличие слотов под заголовки элементов и
  числа, «дыры» (слоты, которые нечем заполнить), разнообразие (штраф за повтор),
  приоритет паттерна из парсера и смещения варианта. Каждое решение сохраняет обоснование и
  альтернативы (видно в UI и manifest).
* **clone & fill** (`builder.py`, `pptx_ops.py`): пример-слайд копируется вместе со связями
  (картинки, медиа), повторитель сокращается с перераспределением элементов, контент
  раскладывается по ролям слотов с сохранением форматирования абзацев/ранов; каждая единица
  контента используется один раз; все незаполненные слоты и их рамки удаляются — заглушки
  шаблона не остаются. Текст вписывается замером реальными метриками шрифта (FreeType) с
  уменьшением кегля **только по шкале шаблона**; что не влезло — пакетно сокращает LLM.
* **compose** (`compose.py`): диаграммы, таблицы, KPI-плитки, процесс/таймлайн (аналог SmartArt
  из нативных фигур), карточки с иконками, списки, цитата — на «холсте» (макет шаблона с
  заголовком), в зоне контента, найденной CV, в цветах/шрифтах/кеглях шаблона, с проверкой
  контраста.
* **Три варианта** (`config/variants.yaml`): ось различий — *плотность × способ визуализации ×
  порядок*. «Сбалансированный» — порядок плана, смесь карточек/текста/данных; «Визуальный» —
  KPI, диаграммы, пиктограммы, изображения, короткие списки превращаются в карточки с
  иконками; «Аналитический» — вывод в начале (пирамида Минто), без разделов, таблицы вместо
  графиков, больше пунктов. Все три используют только паттерны и токены шаблона.

## 5. Аудит (`audit/`) — см. AUDIT.md

Часть пайплайна: сразу после рендера каждого варианта. Детерминированные проверки работают по
файлу, профилю шаблона и пикселям рендера; контекстуальные — VLM по картинке слайда
(вопросы Приложения 1). Безопасные детерминированные находки исправляются автоматически,
остальные пользователь выбирает в UI. Замечания, унаследованные из самого шаблона (например,
серый текст с контрастом 3.2:1), помечаются и не штрафуются как ошибки генерации.

## 6. Экспорт (`export/`)

`.pptx` — только нативные объекты (текст, фигуры, таблицы, диаграммы с данными, картинки);
`.pdf` — LibreOffice; `.html` — один самодостаточный файл: векторные SVG-слайды + скрытый
текстовый слой, навигация с клавиатуры, обзор всех слайдов.

## Универсальность и устойчивость

Подробно, с результатами слепого стресс-теста — [docs/UNIVERSALITY.md](docs/UNIVERSALITY.md). Кратко:

* **Вход**: `.potx/.pptm` — замена content-type, `.ppt/.odp/.otp/.key` — конвертация LibreOffice.
* **Мало примеров**: паттерны берутся и из макетов; поля, кегли, акцент ограничиваются
  пропорциями слайда и проверяются на видимость (акцент ≠ фон), неиспользуемые цвета темы
  игнорируются; палитра дополняется цветами рендера.
* **Разные производители OOXML**: одинаковые `idx` у плейсхолдеров не ломают заполнение
  (геометрия каждого плейсхолдера фиксируется по его паре в макете, поиск — по положению).
* **Сложные фоны**: текстура/фото распознаются по сетке занятости, контент ложится на подложку.
* **Бренд-обвязка**: колонтитулы, номера слайдов и тексты, повторяющиеся у края примеров, не
  считаются слотами и переносятся на слайды из голых макетов.
* **Нативные таблицы/диаграммы примеров** перезаполняются с сохранением стиля.
* **Сбои**: упавший слайд удаляется целиком и собирается нативно; ни одного «пустого» слайда.
* **Вывод модели**: поля не по назначению слайда отбрасываются, пункты нормализуются, заголовки
  на чужом языке и дубли слайдов устраняются; структура проверяется (число разных слайдов,
  связь названия с брифом) с одним раундом ремонта.
* **Три варианта** выбираются по очереди со штрафом за уже занятый другим вариантом паттерн.

## Версионирование скиллов и агентов

`skills/registry.yaml` — активные версии (outline, slide_writer, shortener, visual_audit, fixer,
pattern_labeler, image_style, json_repair); `skills/<skill>/<version>.yaml` — промпт (Jinja2),
параметры модели, формат ответа; `skills/agents/deck_agent/v1.yaml` — воркфлоу (шаги, версии
скиллов, флаги, параллельность). Каждый запуск пишет `manifest.json` с `name@version` и sha256
всех использованных файлов, моделями, телеметрией вызовов и таймингами.

## Работа с неопределённостью

* Нет LLM/сбой провайдера → офлайн-планировщик, колода собирается всё равно.
* Слайд упал при вёрстке → фолбэк на нативный список, колода не теряет слайд.
* Нет подходящего паттерна → compose в токенах шаблона.
* Нет шрифта шаблона → Google Fonts / метрическая замена + предупреждение в профиле.
* VLM-проверки недетерминированы → не применяются без выбора пользователя.
